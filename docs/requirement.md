## 1. 提出问题（业务痛点）
日常用户选购餐饮、酒店住宿、休闲娱乐、景区门票等本地生活团购套餐时，各类优惠分散在美团、抖音团购、携程等多个平台。用户想要找到性价比最高的套餐，存在下面一系列痛点：
1. **多平台切换成本高**：用户需要手动打开多个App/网页，反复搜索同一家门店，逐个记录套餐价格、套餐内容，操作繁琐，耗费大量时间。
2. **套餐信息不统一，难以判断等价套餐**：同一商户在不同平台的套餐命名、套餐规格不一样。比如同一家酒店，美团叫【标准大床房一晚】，抖音叫【大床房特惠套餐】，套餐包含权益、使用条件存在差异，用户很难快速判断是不是同类可比套餐。
3. **优惠规则复杂**：限时券、平台补贴、会员券、满减活动叠加规则各不相同。用户很难一次性计算出套餐最终到手价，容易忽略隐藏限制。
4. **使用约束信息分散**：套餐有效期、预约要求、节假日加价规则、随时退/过期退的退款政策散落在各个平台详情页。用户下单后才发现不能周末使用、无法退款，造成消费踩坑。
5. **缺少横向对比与最优推荐**：用户只能靠人工对比，缺少系统综合评估，无法快速筛选综合最优套餐，容易买到性价比偏低的团购套餐。

> 核心问题总结：本地生活团购优惠分散、套餐标准化程度低，用户人工跨平台比价难度大，很难快速选出综合条件最优的团购套餐。

## 2. 需要完成的任务（业务目标）
本项目要搭建一款**本地生活团购跨平台比价原型系统**，解决上面的比价痛点。
任务清单：
1. 收集多平台模拟团购套餐数据，对商户、套餐信息进行标准化处理，统一字段；
2. 支持用户按照城市、商圈、商户名称、消费类型检索团购套餐；
3. 系统自动匹配同门店的同类套餐，把多个平台套餐汇总在同一个页面；
4. 以表格形式可视化展示套餐全部关键信息，支持排序；
5. 根据价格、套餐内容、使用限制、用户评价等多维度指标，自动推荐综合最优套餐；
6. 提供套餐收藏功能，方便用户后续再次查看对比；
7. 提供后台模拟数据管理能力，可以新增、修改商户与套餐信息；
8. 页面提供跳转链接，点击套餐可直接跳转到对应平台套餐页面；
9. 系统仅做信息聚合对比，不实现下单、支付、核销；使用模拟数据完成业务流程演示。

## 3. 推导系统功能（功能需求，分用户端、后台管理端）
### 3.1 用户端功能
#### 3.1.1 套餐检索功能
- 支持选择城市、商圈范围缩小搜索范围；
- 支持分类筛选：餐饮美食 / 酒店住宿 / 休闲娱乐 / 景区门票；
- 支持输入商户名称关键词搜索；
- 支持附加筛选条件：可退改、无需预约、节假日可用；
- 搜索结果支持按【价格升序】、【性价比综合评分】排序。

#### 3.1.2 跨平台套餐匹配与聚合
- 根据商户名称、地址识别同一家门店，归集该门店在多个平台的套餐；
- 智能区分套餐规格，例如区分单人餐、双人餐、大床房、家庭房，避免不同规格套餐混在一起对比；
- 标准化提取套餐字段：平台名称、套餐标题、原价、售卖价、套餐内含项目、有效期、预约规则、退款规则、节假日限制。

#### 3.1.3 比价信息展示
- 表格化展示多平台套餐信息，关键限制条件（不可退、需要预约）标红提示；
- 展示套餐综合评分，由系统根据价格、权益、使用限制自动计算；
- 每条套餐附带跳转按钮，点击跳转至对应平台套餐页面。

#### 3.1.4 最优套餐智能推荐
- 算法综合多个维度打分：套餐售价、套餐包含权益、退款灵活性、预约门槛、用户评价；
- 在对比页面置顶推荐综合最优套餐，并给出推荐理由；
- 支持切换推荐策略：优先低价 / 优先宽松使用规则。

#### 3.1.5 套餐收藏管理
- 用户可以将感兴趣套餐加入收藏列表；
- 收藏页面集中展示所有收藏套餐，支持再次进入比价页面；
- 可对收藏套餐取消收藏。

#### 3.1.6 用户评价汇总展示
- 聚合模拟多平台商户评分，展示平均分；
- 展示代表性用户评价摘要，辅助判断商户服务质量。

### 3.2 后台管理功能（管理员）
#### 3.2.1 商户信息管理
- 新增、编辑、删除商户信息：商户名称、地址、所属商圈、商户类型；
- 维护商户关联的平台信息。

#### 3.2.2 套餐信息管理
- 新增、编辑、删除模拟团购套餐；
- 录入套餐各项字段：平台、价格、套餐内容、有效期、预约、退改规则；
- 更新套餐价格，模拟平台价格变动。

#### 3.2.3 平台数据源管理
- 维护平台基础信息（美团、抖音团购、携程）；
- 启用/停用某个平台数据源。

## 4. 项目简介
本平台是面向本地生活消费人群的团购套餐跨平台比价原型系统。当前餐饮、酒店、娱乐类团购优惠分散在各大本地生活平台，套餐描述、使用规则不统一，用户手动跨平台比价耗时费力。本平台将多平台同门店套餐信息进行标准化处理，统一汇总展示。用户选定商圈或者商户后，可以一键查看全部平台套餐对比，系统根据价格、套餐权益、使用限制综合计算评分，自动推荐最优套餐。平台仅作为信息聚合比价工具，提供外部跳转，不参与交易、支付与券码核销。本项目为课程小组原型项目，采用模拟套餐数据完成业务流程演示，后续可扩展更多平台、更多消费品类。

## 5. 非功能需求
1. **易用性**
页面布局清晰，比价表格重点标注风险项（不可退、必须预约）；操作简单，减少用户学习成本。
2. **可扩展性**
系统结构解耦，后续可以快速新增团购平台，新增消费品类（电影票、足疗、洗车等）。
3. **可维护性**
商户、套餐、平台数据模型分离；后台管理界面方便维护人员更新套餐数据。
4. **容错性**
套餐存在缺失信息时，明确标注“信息未知”，不强行计算性价比评分，避免错误推荐。
5. **性能**
套餐搜索响应迅速；对比页面加载流畅。
6. **安全性（原型）**
原型系统简化权限，后台仅管理员账号可修改数据；普通用户仅查询、收藏，不可修改套餐数据。

## 6. 业务流程说明
1. 用户进入平台首页，选择城市、消费类型，输入商户名称搜索；
2. 系统检索商户，拉取该商户下多平台套餐数据，自动匹配同类套餐；
3. 系统标准化套餐信息，计算套餐综合性价比评分；
4. 页面展示比价表格与系统推荐最优套餐；
5. 用户查看套餐详情、使用限制，可收藏套餐；
6. 用户点击套餐跳转至对应平台，完成购买（平台外部完成，本系统不介入）。

## 7. 项目范围与边界（哪些不做）
✅ 在项目范围内：

- 套餐收藏

- 爬虫抓取各大平台真实数据
- 用户支付、下单、团购券核销
- 真实消息推送降价提醒
- 用户注册登录体系（可简化为临时本地收藏，可选）
